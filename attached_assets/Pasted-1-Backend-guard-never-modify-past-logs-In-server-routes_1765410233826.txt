1️⃣ Backend guard – never modify past logs

In server/routes.ts (or wherever you handle create/update for logs), add a small helper:

// utils/date.ts (or inside routes.ts)
function isPastDate(dateStr: string): boolean {
  // dateStr like "2025-12-10"
  const today = new Date();
  const todayOnly = new Date(
    today.getFullYear(),
    today.getMonth(),
    today.getDate()
  );

  const [y, m, d] = dateStr.split("-").map(Number);
  const logDate = new Date(y, m - 1, d);

  return logDate < todayOnly;
}

a) Block creating logs in the past

Where you insert logs (something like POST /api/logs):

app.post("/api/logs", async (req, res) => {
  const body = req.body;
  const { clubId, date, dayOfWeek } = body;

  if (!date) {
    return res.status(400).json({ error: "Date is required" });
  }

  if (isPastDate(date)) {
    return res.status(400).json({
      error: "Past logs are read-only. You cannot create new logs for past dates.",
    });
  }

  // ...existing insert logic
});

b) Block updating logs in the past

Where you update an existing log (something like PATCH /api/logs/:id):

app.patch("/api/logs/:id", async (req, res) => {
  const logId = Number(req.params.id);
  const body = req.body;

  const existing = await db.query.managerLogs.findFirst({
    where: (t, { eq }) => eq(t.id, logId),
    columns: {
      id: true,
      date: true,
      clubId: true,
    },
  });

  if (!existing) {
    return res.status(404).json({ error: "Log not found" });
  }

  const dateStr =
    typeof existing.date === "string"
      ? existing.date
      : existing.date.toISOString().slice(0, 10);

  if (isPastDate(dateStr)) {
    return res.status(403).json({
      error: "Past logs are read-only and cannot be edited.",
    });
  }

  // ✅ safe to update (today or future)
  await db
    .update(managerLogs)
    .set({
      // ... your fields
      // amManagerName: body.amManagerName ?? null,
      // etc.
    })
    .where(eq(managerLogs.id, logId));

  return res.json({ ok: true });
});


If you have other routes that modify things “inside” a log (e.g. maintenance to-dos, attachments) and you want those blocked too, you can reuse the same pattern: load the parent log, check date, short-circuit with 403.

2️⃣ Frontend guard – show past logs as “View only”

On your Daily Manager Log Entry page component (the one that renders the big card shown in your screenshot), compute a simple isPastLog.

Assuming you have log.date as "YYYY-MM-DD":

const todayIso = new Date().toISOString().slice(0, 10);
const isPastLog =
  !!log && typeof log.date === "string" && log.date < todayIso;


Or if log.date is a Date:

const d = log?.date;
const today = new Date();
const todayOnly = new Date(
  today.getFullYear(),
  today.getMonth(),
  today.getDate()
);

const isPastLog =
  !!d && new Date(d.getFullYear(), d.getMonth(), d.getDate()) < todayOnly;

At the top of the Daily Manager Log Entry card, right under the title:
