1️⃣ Client-side: request location permission
client/src/lib/useLocation.ts
import { useEffect, useState } from "react";

type LocationState = {
  lat: number | null;
  lon: number | null;
  loading: boolean;
  error: string | null;
};

export function useLocationPermission(): LocationState {
  const [state, setState] = useState<LocationState>({
    lat: null,
    lon: null,
    loading: true,
    error: null,
  });

  useEffect(() => {
    if (!navigator.geolocation) {
      setState({
        lat: null,
        lon: null,
        loading: false,
        error: "Geolocation not supported",
      });
      return;
    }

    navigator.geolocation.getCurrentPosition(
      (pos) => {
        setState({
          lat: pos.coords.latitude,
          lon: pos.coords.longitude,
          loading: false,
          error: null,
        });
      },
      (err) => {
        setState({
          lat: null,
          lon: null,
          loading: false,
          error:
            err.code === err.PERMISSION_DENIED
              ? "Location permission denied"
              : "Unable to get location",
        });
      },
      {
        enableHighAccuracy: false,
        timeout: 8000,
        maximumAge: 1000 * 60 * 60, // 1 hour cache
      }
    );
  }, []);

  return state;
}

2️⃣ Use it in the Daily Manager Log Entry (DMLE)
In your DMLE component
import { useLocationPermission } from "@/lib/useLocation";
import { getWeatherCompare } from "@/lib/weather";

const { lat, lon, loading, error } = useLocationPermission();

useEffect(() => {
  if (!lat || !lon) return;

  (async () => {
    const weather = await getWeatherCompare(selectedDateISO, lat, lon);
    setWeather(weather);
  })();
}, [lat, lon, selectedDateISO]);

3️⃣ UI behavior (important UX detail)
Show clear states
{loading && (
  <div className="text-xs text-muted-foreground">
    Fetching location for weather…
  </div>
)}

{error && (
  <div className="text-xs text-yellow-600">
    Weather unavailable ({error})
  </div>
)}

Optional “Retry” button if denied
<button
  onClick={() => window.location.reload()}
  className="text-xs underline text-muted-foreground"
>
  Retry location access
</button>

4️⃣ Security & permissions (what users see)

Browser prompt:

“Allow this site to access your location?”

You are:

NOT tracking

NOT storing unless you choose to

ONLY using it to fetch weather

This is totally acceptable UX for an internal manager tool.

5️⃣ OPTIONAL (recommended): store location once per club

After permission is granted once, you can save it:

// POST /api/clubs/location
await fetch("/api/clubs/location", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ lat, lon }),
});


Then:

No permission prompt every day

Weather works even if browser denies later

Faster load

But you don’t need this to ship.
